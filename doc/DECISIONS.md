# DECISIONS.md — Architecture Decision Records

This file records every non-obvious architectural decision made in this project, with full context and rationale. Read this before "fixing" anything that seems wrong. What looks like a mistake is often a deliberate decision documented here.

---

## ADR-001 — Headless hooks + default UI, not UI-only

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** The component exposes both a headless hook layer and a default UI renderer. The hooks are the primary deliverable. The UI is a convenience wrapper on top of them.

**Context:** A UI-only component would be simpler to build but would lock host applications into our rendering choices. The scientific claim of this project — that a single component is universal across React applications — requires that the component be substitutable at the UI layer without losing functionality.

**Consequence:** Every behavior must be expressible through hooks alone. If a behavior requires the default UI to function, the architecture is wrong.

## ADR-002 — CopilotKit Python runtime, not LangGraph

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** The backend uses CopilotKit Python runtime to emit AG-UI events. LangGraph is explicitly excluded.

**Context:** LangGraph does not emit AG-UI events natively. Using it would require an adapter layer (approximately 100-150 lines of Python) that translates LangGraph's streaming output into AG-UI's 16 event types. This adapter introduces a translation surface where bugs can hide and where the AG-UI event semantics can be subtly violated. CopilotKit's Python runtime emits AG-UI events natively — no adapter, no translation, no additional failure surface.

**Consequence:** The backend is directly coupled to CopilotKit's Python SDK. If CopilotKit's SDK changes its event emission behavior, the backend must be updated. This is acceptable because the coupling is explicit and localized to `backend/shared/agui_adapter.py`.

## ADR-003 — qwen2.5:7b, not Gemma 3

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** The local LLM is qwen2.5:7b via Ollama. Gemma 3 variants are excluded.

**Context:** Scenario 2 requires reliable tool calling. Gemma 3 4B has limited and inconsistent tool calling support. Gemma 3 12B has better tool calling but exceeds available RAM on the target hardware (MacBook M4 12GB). qwen2.5:7b fits comfortably within 12GB and has significantly better tool calling reliability than Gemma 3 4B at an equivalent memory footprint.

**Consequence:** All scenario tests are validated against qwen2.5:7b exclusively. Results may differ with other models. This is acceptable — the component is model-agnostic at the protocol level; qwen2.5:7b is the validation instrument, not a runtime requirement.

## ADR-004 — SSE only, no WebSocket in v1.0

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** The transport layer is SSE only. WebSocket support is deferred to v1.1.

**Context:** AG-UI is defined over SSE as its primary transport. Supporting both SSE and WebSocket in v1.0 would require a transport abstraction layer, doubling the connection lifecycle code and the test surface. The scientific claim of this project does not require WebSocket — it requires demonstrating invariance across different agent backends, which SSE alone is sufficient to prove.

**Consequence:** Host applications that require WebSocket cannot use this component. This is documented as a hard constraint (C3) and an explicit out-of-scope item (Section 4).

## ADR-005 — No CSS-in-JS, scoped styles only

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** The default UI uses scoped CSS only (CSS Modules or inline styles with a component-specific prefix). No CSS-in-JS library.

**Context:** CSS-in-JS libraries (styled-components, emotion) inject styles into `document.head` at runtime, which violates C7 (zero CSS leakage). They also add significant bundle weight. CSS Modules produce scoped class names at build time with zero runtime cost and zero leakage.

**Consequence:** The default UI requires a build step that supports CSS Modules (Vite does natively). Raw CDN import of the component without a build step is not supported.

## ADR-006 — No mocks, data synthesizers instead

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** Test data is generated by committed, seeded, deterministic synthesizers. Mocks are prohibited entirely.

**Context:** Mocks prove that your mock works, not that your code works. A mock SSE stream that emits the events you expect will pass tests even if the real SSE stream behaves differently. The only way to prove the component works is to test it against real events from a real backend. Synthesizers are permitted for generating structured input data (e.g. a valid `AGUIMessage` object for a unit test) because they produce real data structures — they are not behavioral substitutes.

**Consequence:** Every test that involves streaming requires a running backend. Tests cannot be run in isolation without the local stack. This is a deliberate trade-off: slower test setup, higher confidence in results.

## ADR-007 — Separate scenario backends on dedicated ports

**Date:** 2026-05-12
**Status:** Accepted

**Decision:** Each scenario backend runs on a dedicated port (8001, 8002, 8003). They do not share a server.

**Context:** Running all scenarios on a single backend would require multiplexing logic that adds complexity without scientific value. Separate ports mean each scenario can be started, stopped, and debugged independently. It also means a failure in one scenario backend does not affect the others during parallel development.

**Consequence:** Developers must start the specific scenario backend for the ticket they are working on. The setup sequence in Section 10 of the spec documents this.
